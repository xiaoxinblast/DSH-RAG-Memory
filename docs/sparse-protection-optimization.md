# 稀疏保护检查瓶颈定位与等价优化

日期：2026-11-03。只用合成数据和内存 SQLite；不调用付费模型，不读取真实聊天，不改变日用配置或安装，不提交、推送。

## 结论

针对上一轮稀疏单次保护检查变慢，先完成 CPU 采样、查询计划和读取形式对照，再修改生产代码。瓶颈定位到 SQLite 游标逐行生成带字段名对象的读取路径。改为流式返回位置数组，仅对命中行生成原样结果对象后，三轮交错实测中，稀疏保护检查中位耗时约下降 29%，同时低于更早优化前版本。

生产仅改 `src/store.mjs` 的 `protections`。协议仍为 6，数据库仍为 3，近义阈值仍为 0.5。没有增加规则、缓存、查询次数、运行依赖或部署要求。分支数保持 858 → 858，不宣称本轮再次减少了分支。

## 先查瓶颈

先核对上一轮 release 的 25 份指纹全部一致，再冻结本轮起点 98 个文件，起点生产分支为 858。诊断运行时尚未修改生产实现。

诊断对象为实际 `protections`，10,000 条合成遗忘记录中当前作用域命中 9,300 条。先热身，再对 80 次实际调用做 CPU 采样；随后以同一 SQL、绑定参数和数据进行独立读取形式对照。查询计划显示扫描作用域中的保护记录并按记忆 ID 关联，未改变该计划。

| 独立诊断工作 | 中位耗时 ms |
| --- | ---: |
| 旧墓碑匹配结果读取 | 0.23 |
| 完整保护行：对象游标 | 27.16 |
| 完整保护行：数组游标 | 14.74 |
| 完整保护行：一次性 `.all()`，仅作诊断 | 14.94 |
| 原文范围 JSON 解析与空范围比较 | 3.51 |
| 身份文本与精确比较 | 9.73 |
| 所有行分词与评分，上界诊断 | 12.69 |

这些分项有重叠，不可相加为总时间；CPU 采样会影响执行，不用于最终性能结论。原始 self samples 中大量时间归在匿名/内联调用者，不能伪造精确的 C++ 子函数百分比。游标 `next` 有明显样本占用；同 SQL 的对象/数组对照进一步将可优化开销限定到结果转换形式。

没有把 `.all()` 放回生产路径，以免重新整批载入对象。JSON 范围解析虽然有开销，本轮保持原样；没有为空范围增加另一个判断分支，也没有调整文本规则。

诊断脚本：[profile-sparse-protection.mjs](../scripts/profile-sparse-protection.mjs)。汇总及前后相同查询计划见 [诊断证据](sparse-protection-diagnostics.json)。首次诊断和后续数组对照分别保留在 `.cache/sparse-protection/profiles/before.json`、`before-arrays.json`，CPU 原始采样为同名 `.cpuprofile`；`initial.json` 也保留首次报告副本。数组对照中的绝对耗时与首次采样不同，最终结论只使用下述未启用 profiler 的独立性能测试。

## 改动范围与一致性

旧流程为：SQL 返回完整字段对象 → 精确/近义判断 → 保留命中对象。

新流程为：相同 SQL 范围返回位置数组 → 相同精确/近义判断 → 仅将命中行转成原样对象。

- SELECT 明确列出原有 11 个字段，字段内容和顺序不变。
- 返回对象保持 SQLite 原有的 null 原型；JSON 序列化、字段次序、结果次序都与冻结版比较。
- 原文范围、主体/属性、哈希、文本身份和近义分数判断保持原样。
- `blockedBy`、重记许可、`save` 前的新查询、事务、检查点和版本校验均未修改。
- 不缓存查询结果或旧记录文本；后一次调用仍读取最新版本和墓碑。
- 没有改动候选扫描、排序、召回、注入、协议、提示词、UI 和数据库结构。

新增 API 是 Node 内置 `StatementSync.setReturnArrays(true)`，不增加依赖。当前官方文档说明其使 `iterate/all/get` 返回数组；项目声明下限 Node 24.2.0 的官方源码也注册了该方法。本次实际运行是 Node 25.9.0，下限版本只做源码核查，没有宣称跑过该版本。版本化的 24.2.0 文档缺少此条目，因此未仅凭最新版文档的版本注记判断兼容性。

来源：[Node SQLite API](https://nodejs.org/api/sqlite.html#statementsetreturnarraysenabled)、[Node v24.2.0 官方源码](https://github.com/nodejs/node/blob/v24.2.0/src/node_sqlite.cc)、[v24.2.0 版本文档](https://nodejs.org/download/release/v24.2.0/docs/api/sqlite.html)。

## 前后性能

环境：Windows 10.0.26300、Node v25.9.0、Intel Core i7-13650HX。使用相同合成数据、内存 SQLite，不加载日用配置，也不启用 CPU profiler。

三个版本同时复测：

- original：上一轮性能优化之前的冻结实现。
- before：本轮改动前、存在稀疏退化的冻结版本。
- after：本轮实现。

每个版本/记录数/数据类型执行三轮新进程，按轮次旋转版本顺序；共 36 个独立进程。每个进程覆盖无来源无范围、带来源、带来源和原文范围及属性三种输入，每种先预热 3 次，再计时 15 次。每个表格条件、每个版本汇总 45 次有效测量。输出指纹计算在计时外；全部版本和轮次的完整有序输出指纹一致。
