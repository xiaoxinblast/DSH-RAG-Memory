## 已完成的行为变化

- 提示词统一要求 `{"memories":[]}` 表示没有新记忆；解析器额外兼容裸空数组 `[]`，保留原始审计回答。非空裸列表、坏 JSON、未知字段、无效枚举、缺少来源、超过 12 条或超过 300 字符的模型条目仍被拒绝，不猜测修复、不额外调用模型。
- 明确 `preference/rule/decision/fact/progress` 的含义。`active` 表示陈述已经确认，不代表任务已经完成；已确认的“下周执行，尚未开始”可以是 active。无价值的助手猜测允许不保存。
- 普通项目新增记忆仍自动处理。自动提炼提出的全局共享或带旧记忆目标的条目一律保存为 pending；确认前不参与召回，不停止旧记录，不移除旧向量。
- 替代候选保留目标关联与原快照版本。人工确认在同一事务中检查候选自身版本和旧记录版本，再将旧条目置为 superseded、移除旧索引并激活新条目。旧记录已修改、失效或遗忘时拒绝确认；失败不会留下伪确认来源。
- 重启后版本关联仍有效。同内容、同范围、同旧版本的待确认提议去重；旧版本变化后可生成新的候选，旧候选不能自动更新快照或借机通过确认。
- 既有“纠正 / 确认”入口展示旧内容、状态和读取版本，按钮区分“确认并替代旧记忆”和“确认全局共享”。Agent 不能代替人在此路径确认高影响待确认条目。

数据库仍使用现有表结构：候选使用 `pending`、`supersedes`，目标版本存入现有 `meta` 的 `replacement:<candidateId>` 项，不进行 schema 迁移，不批量重写旧记忆。没有添加或更改 UI invoke 的公开 action／请求字段。既有明确用户请求的工具写入路径仍保留；本次默认待确认策略针对自动提炼及其候选确认。

过去已经存在但缺少目标版本快照的替代候选会拒绝直接确认，需要重新生成；不会为旧候选假定一个当前版本。

## v2 评分口径

- `precision`：已解析正文是否受来源支持且保留必要限定条件，独立统计语义错误。
- `recall`：必需原子事实的语义覆盖率，不因 kind 标签错误把已有的事实覆盖抹掉；缺少事实仍计遗漏。
- `memoryPrecision`／`memoryRecall`：同时满足语义、记忆价值、分类、范围、状态、目标、证据和去重的有效记忆质量，作为另一个指标，不冒充纯事实准确率。
- `errors`：分别计来源不支持、条件遗漏、不值得保存、kind、scope、status、纠正目标和证据错误；分类错误不会被记作正文幻觉。
- 允许一条输出覆盖多个原子事实，也允许分条记录。混合事实的分类可采用其中一种主类型；明确有重叠含义的开发案例预先声明 `acceptedKinds`。这些规则在第二轮调用前冻结，不按某模型答案临时放宽。
- 不强制保存无价值的助手自述：这类开发金标改为 optional，不记录不扣关键事实召回。
- `firstStructure`：包含空数组兼容后的首次结构成功率；`canonicalStructure` 单列规范对象结构率，`compatibleEmpty` 单列兼容次数。传输、JSON／封装格式和字段错误分别计量。
- 完整输出仍要求逐条独立语义复核，明确填写 `supported`、`conditionsPreserved`、`retainable` 和 `coveredFactIds`。关键字命中不代替事实核验，不让被测模型自评。

保留有效记忆精确率≥98%的保守门槛，并单列正文语义精确率≥98%、关键原子事实召回≥90%、首次结构成功率≥99%，错误覆盖／跨项目共享／遗忘复活必须为 0。参数、完整轮次、独立复核和实付费用的完整性门槛继续有效，参考费用不能自动生成成本赢家。

本轮金标和新案例由 Codex 整理并通过控制回放验证，**没有人类第二次审阅**。控制回放验证的是协议与计分流程，不是模型效果；金标仍可在下一轮冻结前接受独立审阅。
