# 记忆写入协议与最终单元整理验收（v7）

本轮完成协议、遗忘操作和最终记忆单元的统一整理，离线验收通过。生产改动限 `src/extraction.mjs`、`src/operations.mjs`、`src/policy.mjs`。没有付费模型调用、真实聊天处理、日用配置修改、安装升级、提交或推送。

这次是宿主写入链路验收，不是千问或 DeepSeek 准确率验收。模型能否稳定输出新协议、正确分组和保留限定条件，仍未实测。

**处理链路与职责**

旧链路：两阶段都展示混合字段声明 → 所有操作共用字段包 → 按提议逐项复核 → 每条提议独立裁决、独立入库。

新链路：按阶段投影字段 → 按动作解析并核查来源 → 独立复核给出 `units/members` → 宿主构造完整记忆单元 → `decideOperation` 唯一裁决 → 原事务提交和凭证。

| 位置 | 本轮处理 | 边界 |
|---|---|---|
| `src/extraction.mjs` | 协议统一为 7；同一字段声明驱动阶段投影、验证与例子；共用基础字段校验 | 不写数据库，不自动修补模型输出 |
| `parseOperations` | 遗忘只收 7 个必要字段，范围取冻结目标快照；`attributes` 省略或 `null` 都归一为空对象 | 不从无关正文猜范围、意图或授权；多余遗忘正文/分类字段按坏项处理 |
| `parseReview` / `finalOperation` | 复核输出最终单元的成员编号，宿主按提炼顺序原样换行连接 | 不接受模型改写正文、目标、范围；不新增改写模型调用 |
| `src/policy.mjs` | 保留单一裁决入口；事实和授权引用独立验证；合并单元逐成员检查来源 | 候选、未决、墓碑、版本和项目约束不能借分组放宽 |
| `src/operations.mjs` | 提交最终单元；检查整体和各成员遗忘保护；保留所有错误凭证 | 不再逐条提交已归入完整单元的子提议 |
| 存储、检索、注入、UI、传输 | 文件指纹保持不变 | SQLite 表、五个工具接口、索引算法、预算、日用路由未改 |

移除的重复判断/要求：两阶段混用的输出字段声明；遗忘动作的正文、分类、范围、属性、事件状态、完整性、重记字段要求；授权引用必须属于事实引用的错误约束；逐条 `decisions` 输出格式。没有保留旧协议的生产回退分支。

`control` 现在由宿主根据遗忘动作确定，模型不再输出该标签；内部裁决仍使用统一操作表示。这不涉及第二套协议版本或自然语言猜测。

**遗忘与来源保护**

- 最小遗忘输入：`action`、`targetId`、`targetVersion`、`evidence`、`authorizationEvidence`、`certainty`、`authorization`。复核同样只要求与遗忘有关的字段。
- 仍要求目标属于给定范围、目标唯一、版本有效、双方明确授权、直接用户来源、复核通过。目标不明保持原状态并记录澄清结果。
- 事实证据与授权证据允许分处不同锚点；复核单方补入的授权不能升级权限，跨项目、辅助上下文或引文不能作为直接授权。
- 执行沿用原 `store.forget` 事务。分离的、双方认可的授权锚点也进入控制来源遮蔽，邻接的独立事实不被整段抹掉。
- 遗忘授权与待写事实落在同一不可分锚点时，两边都保留待检查。对同批“忘掉 A，同时保存 B”，只有可分辨的范围才分别执行。
- 合并单元同时检查整体正文和各成员，防止拼成长正文后弱化单个成员的墓碑匹配；没有改变既有近义阈值或保护索引。

**最终记忆单元**

例如复核给出 `members: ["op0", "op1"]`：

```text
op0: API 监听8123。
op1: API 只允许回环访问。
```

宿主只保存一个正文：

```text
API 监听8123。
API 只允许回环访问。
```

它只形成一条记忆及其索引/召回项，凭证保留成员编号、原提议、证据和复核判断。复核成员顺序变化不改变正文顺序。独立的“项目语言中文”仍单独保存。

分组只适用于普通新增；成员的动作、意图、分类、范围、目标、语义判断、重记标识和属性必须兼容。不同主体/属性的提议不会被强行合并，也不会静默删掉属性。更新、合并旧条目、遗忘、重记保持单项。

单元总正文仍限 300 个 Unicode 码点；超过上限整组待检查，不截掉条件。成员缺失、重复、非法引用、属性冲突或非法复核字段影响相应单元，合法独立单元继续。错误单元不会回退成几条被单独激活的子记忆。

**剩余问题与质量边界**

1. 两个阶段可能同时漏掉条件、误判否定/因果/完成，或者错误拆成独立单元。新增风险用例明确展示：双方都声称两条相互依赖内容可独立使用时，宿主仍会保存两条。没有用关键词规则冒充语义判断。
2. 新协议消除了提示/字段冲突，但未经真实模型验证，不能宣称千问不再输出嵌套包装、DeepSeek 遗忘执行率提升或任意模型准确率提高。坏格式仍按原回答留存、隔离/待检查，不猜测恢复。
3. 分组采用保守兼容条件。即便语义上有关联，分类、主体属性或时间元数据不同也会使整组待检查；不会删掉元数据来强行通过。后续应通过独立语义测试评估漏记率，而不是放宽宿主保护来凑成绩。
4. 当前 DSH 适配链路仍用提示约束 JSON。已检查本机 `@deepseek-ai/dsh-llm` 的调用控制声明并核验回环请求，未传递供应商 `response_format`/严格 JSON Schema；本轮没有增添某一家专用旁路。不能把字段投影误称为供应商强制格式。
5. 提示变长与合并单元的逐成员保护检查可能影响调用成本和耗时。本轮没有做真实模型费用或延迟测试，也没有宣称性能改善。
