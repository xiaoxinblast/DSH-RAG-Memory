# v7 固定逻辑：千问 Flash、27B、DeepSeek 合成实测

测试日期：2026-11-03，北京时间 22:48–22:55。计划指纹：`1673dbbe6189d68aca28a2d1fa6f5f748830a62a2142e8b642c4094bb3123311`。

**三款均未通过本项目既定质量门槛，不据此切换日用模型。** DeepSeek 在本组案例中的覆盖率和端到端速度较好，明确遗忘执行也通过；27B 的有效记忆精确率较高，但遗漏、停留在候选状态较多；Flash 最便宜，但仍存在范围误升、未决计划激活、无授权替代和遗忘格式失败。

本轮没有修改 v7 生产代码、提示词或日用配置，没有提交、推送或部署。所有输入均为合成案例；使用真实 DSH SDK 和供应商接口，结果只进入隔离的内存 SQLite 及本地评估文件。

## 测了什么，怎样评分

- 冻结 48 个案例：32 个此前使用过的回归案例，16 个在生产代码冻结后新写的案例。每个模型运行两遍，共 288 个任务；重复运行不是新的独立样本。
- 共发送 540 次请求：288 次提炼、252 次独立复核。没有有效提议的任务不调用复核。没有重试、备用模型或付费评分调用；所有请求均 HTTP 200、正常结束，没有本轮结果不明请求。
- 所有模型均使用 `temperature=0`、`maxTokens=2048`、90 秒超时；实际请求中关闭思考。未启用云端检索，也未为某个模型单独增加 JSON Schema 配置。
- 提炼和复核使用同一候选模型，但为两个独立请求；不把两阶段同意当成真实正确。
- Codex 对 97 个去重后的“案例＋正文”组合逐项对照原文和冻结标准答案判定，复核包隐藏候选名称；同一正文使用同一判定。没有独立外部人工评审组，语义判分仍存在判断局限。

**指标定义：**

1. **有效记忆精确率**＝正文受来源支持、有持久价值、允许成为有效状态且作用域正确的新有效记录数／全部新有效记录数。旧记录不计入这个分母；旧记录变更另验。此指标不是所有分类、事件元数据的独立全面准确率。
2. **应记内容覆盖率**＝在规定状态及作用域下覆盖的必需标准答案单元／全部必需单元。每遍 40 个单元，其中 36 个要求 active、4 个要求 pending；两遍共 80 个。遗漏和应 active 却 pending 都会扣分。它包括候选状态验收，不能直接称作纯有效事实召回率。
3. **首次完整结构通过率**＝该任务所有实际调用阶段都满足严格协议、无项级解析错误的任务数／96。HTTP 成功或 JSON 可解析不等于严格结构成功；单项错误被隔离后仍可完成任务。
4. **明确遗忘执行**单列旧记录最终状态：4 个明确且唯一的合成遗忘场景各重复两遍，共 8 次，不把“没有新增错误记忆”当成遗忘成功。
5. 每条有效记忆必须可独立使用。端口正文与必要访问限制分开保存，即使两条都在库中，也不能保证召回时一起出现，因此仍判为限定条件不完整。

门槛沿用冻结计划：有效记忆精确率 ≥98%、覆盖率 ≥90%、首次完整结构通过率 ≥99%，错误覆盖、候选误激活等关键错误为 0。小样本中零错误不证明长期零风险。

**评分修正公开保留：** 初始冻结评分器把 27B 的 `units7-new-2` 两遍均计为零覆盖。它实际上分别保存“检索器构建完成”“导入器构建失败”“两个组件均未发布”，这些独立进度维度合计覆盖两个标准答案，不会造成端口权限条件那类脱离限制的问题。语义审计各补回 2 个单元，故 27B 覆盖率从 34/80＝42.50% 修正为 38/80＝47.50%。没有改变原始回答、原评分文件、正文精确率或生产逻辑；修正理由和具体任务在 `audited-score.json` 中另存。这是一处结果后的评分修正，解释结果时应保留这一限制。

## 已核对的失败案例

| 案例及模型 | 实际结果 | 归因与影响 |
|---|---|---|
| `v3-actions-4`，Flash 两遍 | “忘掉邮件索引使用 SQLite，同时记录导出为 NDJSON”：NDJSON 入库，但 SQLite 旧记忆仍 active | 遗忘复核额外输出 `restores`、`eventState`、`unit`，不符合最小遗忘协议。坏项被隔离，独立新增成功；遗忘未完成。四个明确遗忘场景共 0/8。 |
| `negation-1-2`，Flash 两遍 | 本项目离线 SQLite／线上 PostgreSQL 被存为 global | 双阶段把项目陈述当作全局授权。真实引用和双阶段同意不足以证明语义授权正确。 |
| `fresh-v5-9`，Flash 两遍 | “尚未确定先调整批处理还是下载器重试”存为 active | 未决选择被双方判为已确定；结构合法，语义错误。其他两个任务也出现候选误激活。 |
| `v3-actions-3` 两遍、`units7-new-6` 第一遍，Flash | “不要忘掉，仍然有效／继续保留”触发替代 | 原有效记录退出当前状态，产生不必要新版本。另一次还保存了“不要忘掉……”控制句。不能描述为物理误删。 |
| `holdout-reference-1`，DeepSeek 两遍 | 一条存“API 8123、界面 8124”，另一条存“仅回环地址、不对外” | 必要访问条件未与端口事实形成同一个可独立召回单元。两阶段均认为各条 self_contained，v7 未纠正这一语义错误。 |
| `units7-new-1`，27B 两遍 | “图谱预览服务监听 7351”与“仅 127.0.0.1、禁止局域网及公网”分开存 | 与上一行同类，不能因限制另有一条就算端口条目完整。 |
| `roles-1-2`，DeepSeek 两遍 | 存入“用户先不要确定邮件索引方案，要继续比较” | 按冻结标准，这是缺少最终结论的当前对话指令，无需进入持久有效记忆。 |
| `fresh-v6-3`，27B 两遍 | “DNS 切换后中断，先后已确认、因果未确认”的完整限定事实存 pending | 把因果未知扩散为整个已确认观察未知，压低覆盖率；不能靠精确率较高掩盖。 |
| `v3-actions-8`，27B 两遍、DeepSeek 第一遍等 | `attributes.core` 输出字符串、null 或对象，提炼项被拒 | 当前提示词列出 core 字段，却未明确其布尔类型；解析器仅接受 boolean。包含宿主契约说明缺口，不能全部归咎模型。 |
| `v3-actions-4`，27B 第一遍 | 遗忘成功，但新增项复核多包一层 `review`，新增项无效 | 说明坏项隔离有效，同时严格结构仍失败；整批“完成”不代表所有业务动作成功。 |

完整失败记录包括原文、标准答案、最终状态、操作凭证和失败指标，保存在本轮 `failures.json`。原始模型输出、实际请求设置、用量和审计保存在 `live/responses.jsonl`、`live/journal.jsonl`。

本轮能确认 DeepSeek 在这 8 次明确遗忘检查中成功，不能据此断言所有遗忘表达都已解决。新协议和数据组成与历史轮次不同，本报告不把历史成绩与本轮相减并宣称准确率提升。

## 结论与未解决的问题

1. 保留当前日用模型与部署状态。DeepSeek 可以继续作为后续对照，但本轮尚不满足本项目质量门槛；27B 不能仅凭精确率高于其他两款就替换，Flash 也不能仅凭低价成为默认。
2. 需要区分两类缺口：`attributes.core` 类型说明和遗忘最小字段属于协议可靠性；必要限定条件、无价值指令、范围及候选授权属于语义判断。当前两阶段仍可能一致犯错，严格格式校验无法解决后一类。
3. 本轮只固定逻辑测量，没有据失败案例改提示词、增加词表、调整生产策略或追加付费调用。后续若修订协议，应保留本轮原回答与评分，另立版本验证，不能拿改后回放冒充原模型成功。
