- 提议内容合格要求事实受来源支持、有持久价值、保留必要限定；它不是仅检查 JSON。生效记忆额外检查激活授权及作用域，分母仅新建的 active 条目。

- 完整行为通过同时要求任务结束、全部必需事实覆盖、旧状态正确、无关键违规、无错误生效条目；格式成功率另列，不相互代替。
- 预设门槛：内容及生效记忆合格率 ≥98%，关键事实覆盖 ≥90%，首次结构 ≥99%，关键违规为 0。三者都未通过。

千问 Flash 的生效记忆合格率 98.15% 不能单独用于宣布达标：它只覆盖了 63/102 个必需事实。DeepSeek 覆盖最高，但仍有错误生效条目和遗忘保护违规。本结果是“冻结提示词、协议、宿主策略、SDK 路由与模型”的联合结果，不是通用智能排名。

## DeepSeek 的回退是否解决

只可确认部分案例改善，不能认定整体解决：

1. `fresh-v6-1`：“清理任务或压缩任务先启动哪个尚未决定”。历史 v6 两遍均误激活；本次首遍正确为 pending。该场景的第二遍尚未执行，因此没有双遍稳定性结论。
2. `fresh-v6-2`：已决定周二迁移备份、是否更换日志引擎仍在讨论。本次分别为 active 与 pending。
3. DNS 切换先后与未确认因果、证书过期导致同步失败、归档获授权但未开始、前端已完成与后端未完成等首遍案例正确保留原意。
4. **新/仍存在的失败**：`forgetting-1-2` 将“重启后保持遗忘旧方案，不要从日志恢复”保存为新的 active 规则，带回了被遗忘内容。原 forgotten 条目未复活，但新表述重新进入了有效记忆。历史 v6 的该案例没有这项错误。
5. `holdout-reference-1`、`fresh-v5-5` 把端口事实与“只允许本地访问、禁止外部访问”分开保存；端口条目丢失必要限制。两个模型阶段都批准了这种拆分，不能视为系统已保障语义安全。

本次首遍：候选误激活、跨项目修改、原 forgotten 条目复活、未授权覆盖均未观察到；DeepSeek 的遗忘内容包装成新规则共 1 个案例。样本内为 0 不等于长期无风险。历史比较仅用于定位同一案例的行为变化，不给旧回答补新协议字段，也不把历史结果当成当前质量证明。

## 失败类型及可复核证据

所有 134 个有遗漏、错误生效、旧状态不符、任务失败或格式问题的任务，详见 [逐案例失败报告](<D:/AI/AI agents Project/DSH-RAG-Memory/.cache/extraction-evaluation/kernel-v7/failures.json>)。以下是实际观察，并非推测模型“能力不够”：

| 机制/案例 | 证据与影响 |
| --- | --- |
| skip 格式约定不一致 | 当前提示词写“skip 可仅含 action/evidence”，解析器实际仅接受这两个字段；Flash 有 28 个 skip 项携带其他字段而被判无效，DeepSeek 2 个。这里有提示与解析契约的问题，不能全部归因于模型智力。 |
| 复核扩大引用范围被拒 | 27B 有 23 个复核项、Flash 10 个、DeepSeek 4 个引用了该条提议原始 evidence 以外的合法锚点，违反当前严格子集约束；常见起点是提炼只引用句首，但正文包含后续条件，独立复核试图补齐证据。数量为全 417 个任务的“项数”，不是案例率。 |
| 明确事实被相邻否定影响 | Flash 在“原因尚未查明；邮件索引已经恢复运行”中，复核将因果否定扩大到恢复事实，导致漏记。相关复核同时存在引用契约错误，不能只归为单一语义原因。 |
| 因果预设 | 第二遍出现“SQLite 导致故障的原因尚未查明”，前文已预设因果；后接“不能记为事实”并不能消除前文冲突。按内容错误记录。 |
| 两阶段语义一致仍会错 | 遗忘指令变规则、端口条件分离都有两阶段批准实例；统一复核不等于事实保证。 |

需要优先处理的是明确的协议契约矛盾、证据完整性，以及遗忘和限定条件这两类联合失败。**本轮没有修改这些生产逻辑，也没有追加词表、规则或提示词补丁。** 后续若继续整理，应先明确契约与离线验收，再另定实施范围。

第二遍只运行了每个模型前 19 个场景，覆盖面与完整 120 场景不同，不混入主准确率。所有原始失败和中断都保留在分母及费用记录中。

- 两次 DeepSeek 收到 HTTP 200 后 90 秒超时，分别预留 ¥0.048632、¥0.047972。
- 一次 DeepSeek 返回 HTTP 503，预留 ¥0.047756；不假定错误请求免费。
- 全局停止护栏还拦下 4 次尚未发送的复核，不计模型调用或费用；相应案例仍记为首次失败。
- 中断后仅在无凭据 HEAD 连通性检查及日志核对后继续未开始任务；已尝试任务没有重发。两次续跑检查点、旧评估脚本、原始计划均留档。最后收到明确 503 后未继续发送。
