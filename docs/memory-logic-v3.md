# DSH-RAG-Memory 整体逻辑优化与验收

日期：2026-11-03。**已完成源码与构建产物的 v3 逻辑调整、离线回归、真实 SDK 回环、合成旧格式升级恢复和实际界面验收。未部署到日用 DSH，未进行新协议的真实模型质量测试。**

当前包版本仍为 0.1.3，本次是源码开发版，不表示已发布新版本。没有新增依赖或常驻服务，SQLite、本地数据目录与五个工具名称保持。机器摘要与证据指纹见 [memory-logic-v3.json](memory-logic-v3.json)。

## 当前处理链路

```text
新文本事件 → 遮蔽凭据、分片及覆盖范围 → 增量批次＋有限相邻上下文
       → 关键词／主体／已有向量寻找相关旧记忆
       → 一次 v3 提炼 → 来源、范围和操作策略检查
       → 高影响操作集中进行一次同模型独立复核
       → 事务写入／合并／待确认／澄清／拒绝＋操作凭证
       → 当前有效事实 → 关键词／向量／主体融合与精排
       → 受分层预算约束的每轮记忆快照
```

当前 DSH 运行入口使用 v3 操作方法；保留旧封装供历史回放和原有测试使用，v3 失败不会退回旧提炼协议。前两轮模型报告、金标、首次回答与采集流水没有被重写；不能用本轮控制测试更新旧模型准确率。

## 已实现的行为

### 采集与来源

- 保留四轮／空闲两分钟的增量触发，忽略历史事件、插件消息和子代理。
- 来源分片记录原消息、分片编号、字符覆盖范围与截断情况。每消息仍有采集上限；界面明确显示未覆盖全文，不能将局部处理说成全文导入。
- 批次最多附带两个相邻片段，每段最多 600 字节，标记为辅助上下文。不能只引用辅助上下文新增记忆，处理检查点只推进本批新来源。
- 提炼输入保守上限 8,000；复核输入上限 16,000，以容纳来源、目标快照及多个操作。仍使用 temperature 0、2,048 输出上限、90 秒阶段超时，无主聊天历史、工具或供应商 Schema 参数。
- 操作绑定 JavaScript UTF-16 原文范围。宿主检查编号、边界、引句、角色、引用和所在语句的否定／条件，避免通过裁掉限定词制造授权。这些规则有保守拒绝，不等于完整语义证明。

### 自动写入与更新

内部协议为 `version: 3`，操作包含 `add / update / merge / forget / skip`，并区分陈述、记住、纠正、遗忘、查询、临时要求、引文和明确重新记住。

| 情况 | 处理 |
|---|---|
| 有来源、无冲突的普通项目新增 | 自动生效，不增加独立复核调用。 |
| 明确全局偏好、纠正、近义合并、唯一目标遗忘 | 同批集中复核一次；通过来源、意图、范围及版本检查后生效。 |
| 复核拒绝 | 留下拒绝凭证，不写入有效记忆。 |
| 复核不确定、写入目标版本变化或历史元数据不足 | 保存候选，原结论继续有效；不能用旧快照覆盖新版本。 |
| 遗忘目标缺失、无法从原话唯一核对 | 留下需要澄清的结果，不猜目标、不遗忘。 |
| 查询、临时要求、引文、把遗忘改成继续使用 | 拒绝或跳过，不能变成持续规则。 |
| 结果不明、超时或复核协议无效 | 任务停为需要检查，保留来源检查点，不自动重发调用。 |

完全重复的有效或待确认条目补充证据，不重复建条目或向量任务。近义合并必须复核，保留原正文及所有来源；分类、适用时间不一致时保留候选。同主体／属性已有不同结论的普通新增不会直接生效；唯一冲突目标会关联为替代候选。

明确纠正以事务保存新条目、旧条目退为历史、移除旧索引并记录前后快照。明确的进展更新同样保留旧阶段历史，不宣称过去阶段本来就是错误。未发生后续编辑、遗忘或替代时，用户可在界面按版本回退自动纠正。

后台和 Agent 工具共用操作策略。普通显式工具新增可本地执行；高影响工具操作也需复核。工具处理不把整条用户消息标记为已提炼，避免遗漏同条消息的其他事实。跨项目查询核对当前真实用户原话中的完整路径，不能仅靠工具参数放宽范围。

### 遗忘及重新记住

- 停止当前／历史检索，清除条目向量和查询缓存，失效召回快照与关联候选。
- 新墓碑记录事实、作用域、原文范围、主体／属性与来源顺序水位；不因共享来源就阻断其他事实。旧墓碑继续使用保守阻断，不猜测原来的精确范围。
- 后续提炼及辅助上下文遮蔽已遗忘来源范围，保留字符索引。整批内容已遮蔽时不再调用模型。遗忘发生在提炼／复核期间，旧批次退出，不继续复核或写回；未处理的其他范围另行排队。
- Agent 读取工具不返回已遗忘正文，重复工具请求也不会重放旧结果中的正文。用户管理界面仍可查看本地审计。
- 明确重新记住要求晚于遗忘的新来源和单条事实授权，创建新记录，旧记录仍为 forgotten。仅靠改写、旧来源或回放不能复活。

遗忘是停止使用和阻断后续写回；本地来源、审计和修订仍保留，也无法撤回此前已发送给模型的内容。主体／属性识别及独立复核仍有模型依赖，不能宣称已解决所有近义改写或长期遗忘风险。

### 检索、时间与注入

- 项目／全局范围先过滤再排序截断。关键词、主体、向量候选通过 RRF 融合，最多八条精排、五条注入；云端总等待仍最多两秒，超时回退本地通道。
- 普通召回排除 pending、superseded、forgotten 及明示过期条目。可选 `history: true` 包含已替代及过期历史并标记历史性质，始终排除 forgotten；`at` 可提供明确 ISO 查询时间，纯日期按香港当日日末处理。未标注适用时间的记录不被伪造为某日确认有效。
- 只有来源明示日期或精确时间才写入适用时间。日期级起止按香港自然日处理；来源未写精确时刻时，拒绝模型补出精确时刻。没有使用“七天没访问就删除”等年龄淘汰规则。
- 稳定全局核心先使用最多 400 保守 Token，其余优先留给相关记忆；总正文上限 1,500、最多五条，闲置预算可借用。每条完整注入，预算不足时记录排除原因。
- 数据变化增加快照代次标记，同一用户消息的下一工具步骤也能丢弃旧快照；不在每次工具后续步骤重复检索。

## 数据升级、恢复与回退

开发版 schema 为 3。新增 `memory_attributes`、`evidence_ranges`、`forgotten_facts`、`memory_operations`、`job_stages`，并扩展来源分片及任务租约字段；原记忆 ID、正文、来源、修订及状态保留。旧元数据标记 legacy，旧召回缓存失效，不批量重提炼旧聊天。

任务租约为两分钟，每 30 秒续租，携带执行令牌；过期执行者不能提交。输入、提炼和复核阶段分别保存指纹与结果，本地事务失败可复用已完成回答。模型暂不可用时保留队列，不增加调用失败次数或切换模型。暂停云端后，高影响操作不绕过暂停；普通显式本地写入仍可用。

“重试失败任务”仅恢复可安全重试的任务；模型发送后结果不明的阶段留待检查，不据此再次扣费。界面目前提供状态、原因和操作凭证，没有服务端账单对账或“确认重发未知调用”功能。服务关闭会等待后台与工具请求退出，再关闭数据库。

以后部署时应：

1. 停止日用写入，对旧库做 SQLite 一致性备份，验证 `integrity_check`，同时备份对应 profile 和安装包。
2. 先用隔离副本启动新版，核对原表内容、legacy 标记、任务状态及界面；确认后再决定日用切换。
3. 需要退回旧插件时停止新版，恢复升级前的一致性备份与对应插件／profile。不能仅换回旧包、删除新列或覆盖仍在使用的数据库；升级后的新记忆应另外保留。

本轮只在合成旧格式数据库中执行了上述升级、幂等重开及恢复验证，没有读取或升级日用数据库。
