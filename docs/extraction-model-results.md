# 国内提炼模型首轮隔离结果

日期：2026-11-03，Asia/Hong_Kong。结论：**暂不切换默认模型；先消除提炼协议歧义并强化来源、作用域和纠正规则。Qwen Flash 保留为下一轮低成本主候选，27B 保留为对照，35B-A3B 暂降优先级。现用 DeepSeek 保持原状，不代表它已通过本轮验收。**

## 本轮究竟验证了什么

执行窗口为本地时间 00:46:13 至 00:54:18。160 个合成中文案例，每模型两遍，各 320 个任务，共 1,280 条首次结果；实际传输 1,279 次，其中一条基线任务在发送前发生隔离适配错误。没有补跑失败任务，没有自动回退、格式修复重试或模型切换。

案例由 40 种语义模式 × 4 个项目场景组成，不是 160 种独立语义模式。范围覆盖否定、条件、计划与完成、角色、项目／全局范围、旧记忆纠正、重复与指代、遗忘保护、临时内容及合成凭据。

使用原始 `createDshExtractor`、原提示词和生产的 `MemoryService` 回放入库；输出上限 2,048、temperature 0、90 秒超时。没有发送主对话、工具或金标，没有请求 `response_format`。Qwen 使用北京业务空间 OpenAI 兼容端点；DeepSeek 使用官方账户 Messages 端点，原入口选择 SDK 提供的最低档 `off`。发包检查确认实际 Qwen `enable_thinking:false`，DeepSeek `thinking.type:disabled`。

语义复核由本次 Codex 助手完成，不调用被测候选模型自评，也未使用另一个付费模型判分。对去除型号、将四场景实体替换为占位符后完全相同的输出共享判断，392 组变体映射回全部 1,280 条结果；每条仍单独验证字段、来源编号和宿主状态。**这不是人类金标二审，也不能当作无争议的精确测量。**

## 语义与严格验收必须分开

| 模型 | 已解析正文的来源支持率 | 严格有效条目精确率 | 严格关键事实召回 |
|---|---:|---:|---:|
| Qwen3.7 Flash | 191／200，95.50% | 50.50% | 45.09% |
| Qwen3.5-35B-A3B | 208／217，95.85% | 47.00% | 45.54% |
| Qwen3.5-27B | 173／189，91.53% | 64.02% | 54.02% |
| DeepSeek Flash | 260／266，97.74% | 52.26% | 62.05% |

“来源支持率”只问已解析正文是否被给定来源支持，不验证分类、作用域、是否值得记忆，也排除了无法解析的回答，**不能代替总体准确率**。

冻结评分器中的“严格精确率”要求正文及条件、`kind`、`scope`、`status`、`targetId`、纠正标志、证据和去重均满足金标。它不是纯粹的事实准确率。例如正确的迁移状态被标成 `fact` 而非金标的 `progress`，仍会被计为不合格条目。来源支持率与严格率的差距不能全部归因于幻觉。

严格召回还受到本轮金标粒度影响：金标把“恢复且原因未知”“选择且仅在当前项目启用”等设成组合事实，拆成两条时可能无法获得覆盖分；金标还要求对某些助手猜测保留 `pending`，而原提示词允许不提炼缺少价值的信息。**因此这套分数适合定位当前协议问题，不适合用来断言某模型的通用提炼准确率只有约 50%，或给四模型做能力排行。** 后续应先二审金标、细化原子事实及可接受替代答案，再冻结新版本。

原门槛为严格精确率≥98%、关键事实召回≥90%、首次结构成功率≥99%，且严重错误为 0。本轮没有任何型号满足全部要求。基线还因一条发送前的接入失败而无法通过“每条实际参数均验证”的完整性检查；机器报告保持 `PARAMETERS_UNVERIFIED`，不隐藏此缺口。全部任务和语义复核已结束，`INCOMPLETE_COMPARISON` 指的是公平比较的条件未全部满足，不是还留有未运行任务。

## 具体失败与宿主保护

1. **空结果协议矛盾。** 原提示词前面要求“没有值得记忆的内容返回空数组”，末尾则要求 `{"memories":[...]}`。千问常返回裸 `[]`，JSON 本身合法，但当前解析器只接受 `memories` 对象。本轮不改提示词、不修复回答，保留为首次格式失败；不能将这部分全部解释成模型不理解事实。
2. **助手自述。** `roles-1-1` 中只有助手声称完成。三个千问的某些回答直接写成已完成、已验证。生产宿主把纯助手来源降为 `pending`，本例未作为已确认事实入库；这是已有保护有效的证据，不是线上错误确认的证明。
3. **错误纠正。** `correction-1-2` 用户明确“尚未决定，继续使用 SQLite”，Flash 第一次以及 35B-A3B 两次却输出 `targetId` 和 `explicitCorrection:true`。宿主因此把仍有效的旧记录置为 `superseded`。这项需要同时改进提炼策略与宿主纠正边界。
4. **全局提升。** 在没有跨项目长期个人规则的来源中，35B-A3B、27B、DeepSeek 均有回答写成 `global`。现有 `rule` 分支没有完全阻止这类提升。本轮没有观察到原遗忘条目复活，但部分模型仍把“不要恢复旧方案”再保存为一条新规则，属于过度记忆，不能因墓碑计数为 0 就判定全部行为理想。
5. **遗漏和状态混淆。** 有些回答漏掉已确认事实，或把“已经确认尚未开始”写成 `pending`。需要明确 `active` 表示记忆被确认，未完成的工作本身也可以是已确认状态。

## 接入失败不能算作模型语义错误

| 模型 | HTTP 200 | HTTP 400 | 无响应／发送前失败 | 合计 |
|---|---:|---:|---:|---:|
| Qwen3.7 Flash | 315 | 3 | 2 | 320 |
| Qwen3.5-35B-A3B | 317 | 3 | 0 | 320 |
| Qwen3.5-27B | 316 | 3 | 1 | 320 |
| DeepSeek Flash | 316 | 0 | 4，其中 1 次未发送 | 320 |

初期隔离配置错误由本次实现引入：Qwen SDK 默认将系统消息转换为百炼不接受的 `developer` 角色；DeepSeek 的手动适配器少了空扩展回调。后续配置为 `supportsDeveloperRole:false` 并补齐 SDK 注册时已有的空回调，使用下一条未执行案例继续，没有重试失败案例，也没有改生产提炼入口。HTTP 400 返回的实际错误为 `developer is not one of ['system', 'assistant', 'user', 'tool', 'function']`。其余无响应保留为传输失败，不能据此推断模型能力。

修正后本地真实 SDK 回环进一步验证 Qwen 首条消息为 `system`，且关闭思考字段仍在。由于初期接入条件发生变化、失败样本未补跑，本轮属于协议诊断；要形成干净的可替换结论，需要下一轮独立冻结和验收。

## 下一轮优先级

- **P0：统一空结果协议。** 明确始终输出 `{"memories":[]}`，补正反例，再做独立版本测试。是否增加供应商 Schema 作为另一个受控变量，不混入原始协议对照。
- **P0：限制写入风险。** 项目到全局的提升需要独立的显式来源约束；替代旧条目需要真正的纠正依据，不能只信模型的布尔值。保护原来源、旧版本、墓碑及手动回退。
- **P1：统一分类与验收。** 补充 `fact/progress/decision` 和 `active/pending` 定义；人类二审金标，拆开组合事实，允许语义等价答案，单列“未记录不值得保存的推测”。
- **P1：重新对照 Flash、27B 和 DeepSeek。** Flash 已知用量成本最低，但不能直接替换；27B 此轮空数组较少且未错误失效旧记录，仍有全局提升。35B-A3B 本轮两项写入风险较多，尚未体现足以优先使用的收益。以上只适用于此轮，不推广为型号的普遍强弱。

本轮没有修改生产提示词、接口、数据库格式、界面、日用部署或模型配置；没有将真实对话发送到新供应商。凭据只在内存中解析，未写入测试文件。前后核对日用设置、凭据文件和 desktop patch 哈希一致。未提交或推送新增评估文件，未自动切换模型。
