# 原文准入与撤销：隔离实验结果

**结论：继续保留 v7，不接入日用。原文入口的准入和按单元撤销可以正确执行，但没有解决上游错误批准、缺失限定条件引用及未知跨语言事实身份；同范围复杂度也没有下降。** 这是一次已完成的隔离验证，不是已通过替换验收的版本。

日期：2026-11-04（Asia/Hong_Kong）。仅使用合成案例和此前合成评估的冻结回答，新付费调用为 0。没有读取真实聊天、日用配置或凭据，没有改生产接口、源码、数据库格式、UI、模型配置或日用部署，没有提交或推送。

## 实际实现及边界

新代码全部位于 `experiments/admitted-evidence/`，不在插件发布清单内。原 `experiments/evidence-routes/`、历史报告与回答保留原样；轻量索引不进入本轮新路线或性能执行。冻结清单共 354 个源码、配置和历史证据文件，前后 SHA-256 一致。

运行链路：

```text
v7 已生效操作凭证 + 原文范围 + 宿主提供的已知来源关联
    → 登记只含凭证指纹、来源指纹及关联的单元清单
    → 每次读取核对凭证、记忆状态/版本、项目/有效期
    → 核对原文范围、来源变化、缺片/截断及已有遗忘保护
    → 从原文取出完整单元 → 原文关键词匹配 → 整单元预算
```

- 不接受来源 ID 充当准入凭证，不因搜索命中而升级候选或拒绝结果。
- 原文正文按精确范围读取，保留角色、顺序及范围标记；不生成摘要、不补上下文、不截掉条件后输出主句。
- 同消息的 A、B 有独立准入凭证与范围时，忘 A 不连带屏蔽 B。条件属于同一单元时，条件失效使整个单元退出。
- 已知复制/翻译关联由宿主提供。派生项继承原项的撤销；登记后不允许覆盖关联，完整清单的 JSON 往返和重建读取器保留关联。没有实现自动关系发现，也没有接入生产持久化流程。
- 查询每次重新验证当前状态，不缓存可继续注入的旧正文。查询不写记忆或审计。
- 重用现有精确遗忘保护。近义相似度仍由冻结 v7 在准入阶段处理；读取层不再用相似度撤销已经准入的不同主体事实。这不是调整 v7 阈值。
- 有明确新授权的重新记住使用新记录、新来源和现有授权校验，旧 forgotten 记录不恢复。

可信边界：凭证数据库与完整单元清单是宿主内部输入，不是 Agent 可填写的参数。指纹用于检测登记后的变化，不证明模型判断正确，也不抵御恶意修改整个宿主数据库或清单。缺少准入或完整范围的旧记录不会自动迁移；旧记录在 v7 中仍照常可读。

“不保存”在此实验中的含义是不得进入可使用的记忆及原文召回；原文仍可能存在于本地来源/审计库。没有实现或宣称物理擦除。

## 回放结果：没有补写历史模型字段

原样重放 288 个任务、540 个阶段回答。只映射本轮隔离库产生的记忆 ID；不补引用、不补来源关系、不改模型回答或旧评分。正文、分类、状态、范围、版本、替代关系全部与冻结 v7 相同。

使用此前固定 24 项查询，在三模型两遍状态上形成每路线 144 次查询。旧 v7、旧原文的数值来自冻结对照文件；本轮执行新路线，轻量索引不执行。这是宿主回放及字面内容契约，不是新模型准确率，也不是最终回答质量。

| 检查 | 冻结 v7 | 旧整窗原文 | 本轮准入原文 |
|---|---:|---:|---:|
| 限定条件同单元完整出现 | 37/54 | 54/54 | **37/54** |
| 成功遗忘后，独立 B 仍返回 | 7/8 | 0/8 | **7/8** |
| 闲聊/明确不保存被返回（越少越好） | 0/12 | 12/12 | **0/12** |
| 成功遗忘后内容重新暴露 | 0/16 | 0/16 | **0/16** |
| 项目隔离发生泄漏 | 0/6 | 0/6 | **0/6** |
| 已确认全局偏好跨项目返回 | 6/6 | 0/6 | **6/6** |

54 次限定条件查询来自 9 项查询×6 组历史状态，不是 54 个独立案例。所有查询的 `completeUnit` 判定逐项与冻结 v7 相同；原文读取没有补回 v7 没有引用的限定条件。单纯的整窗上下文优势，在严格继承准入后消失。

本轮全部 144 项查询的禁用内容命中为 0，但**不能据此宣称修复了遗忘执行失败**：没有本轮准入凭证的历史种子记忆被整条排除，其中也包含因上游格式失败而没有成功遗忘的旧记录。它们在 v7 中的状态没有被修改。未准入的正常旧记忆同样受限，这是能力收窄，不是更准确的遗忘识别。

## 机制通过与产品未通过分别记录

1. 原原文路线三项验收重新执行，仍是 **0/3**，原测试、实现和历史结果未修改。
2. 新机制初批 17 项中 16 项通过、1 项失败：读取阶段重复近义判断误伤不同主体事实。修正这一职责后，加上重记和审计边界案例，最终 **19/19**。
3. 本轮产品验收保留原三项的来源和输出断言，再增加三项错误批准对照，结果 **2/6 通过、4/6 失败**。失败是实际断言失败，未改成 expected failure 或跳过。
4. 现有生产测试首轮 **171/176**，5 项真实 SDK 本机回环受环境连接限制失败。保持外网防护、在允许回环的环境单独重跑后 **5/5**，合计现有 **176 项通过**。不是重新调用供应商模型。
5. 生产源码检查和全部新实验模块语法检查通过。无 UI 改动，不声称做了视觉验收；未重建或部署日用安装。

机制测试包括：不保存与允许保存共处一条消息、同消息/跨消息忘 A 留 B、整单元条件撤销、候选/拒绝/不完整结果不能升级、未知凭证/未知父项、版本与项目范围、来源/凭证变化、缺片/截断、旧墓碑保守保护、全局权限、有效期、5 条/1,500 字节上界、只读查询、清单往返、已知跨语言继承及新的明确重记。

仍失败的产品条件：

| 失败 | 实际表现 | 为什么没有继续“补规则” |
|---|---|---|
| B 只在原文中，尚未准入 | 忘 A 后仍不返回 B | 自动放行 B 需要准入判断，不能用“剩余文字”替代授权 |
| 跨语言新来源没有关联且被 v7 错批 | 英文等义句仍返回 | 范围和指纹不能识别未知事实身份 |
| v7 把遗漏条件的范围批准为完整 | 只返回主句，不能补回未引用的条件 | 自动补整窗会重新带回不保存/遗忘内容 |
| 两阶段都把明确不保存错批为普通事实 | 该原文仍返回 | 门禁执行批准结果，不能证明批准结果的语义正确 |

原三项中的两个新通过项，源于“没有准入就不返回”；同时有正向测试验证准入的 B 能正常返回。不能把仅拒绝未知来源的通过数当作不保存意图或跨语言语义识别准确率。

## 复杂度对照：没有宣称同范围下降

统计仍使用 AST 的 `if`、条件表达式、逻辑表达式（含 `??`）、非默认 `case`、`catch` 和循环节点。

| 范围 | 分支数 |
|---|---:|
| 生产 src/dsh，前→后 | **854 → 854** |
| 旧原文模块完整范围，含索引提示 | 41 |
| 其中仅索引提示生成块 | 11 |
| 旧模块扣除上述块 | **30** |
| 新准入原文完整运行模块 | **32** |

30 中仍包含没有继续裁剪的索引分数表达式，已经不是“41 对 32 就减少 9 个分支”的叙述。扣除暂停功能后新模块净增 2，**没有证明同范围复杂度下降**。两边均另外复用未变的存储保护与引用检查，不能把它们隐藏起来宣称完整内核很小。

新模块没有语义词表、意图正则、翻译模型、第三个模型阶段、数据库升级或新依赖。结构上的收益是职责可定位：准入决定来自凭证，读取只有一个当前状态与证据门禁，预算按整个单元执行。历史原型保留为冻结证据，因此仓库总实验代码增加，生产路径没有减少。

所有新模块（包含测试、回放、性能和报告工具）的分支统计列在配套 JSON 中，运行模块只有 `route.mjs`。没有把判定挪到新的隐藏辅助模块。

## 性能：读取次数减少，仍不适合直接接入

同一合成内存 SQLite，所有事实有完整引用和明确标记的模拟成功凭证，1 个遗忘条目。三路线交替次序，预热 1 次、测量 5 次；v7 使用不同消息 ID 避免召回快照。无云端向量或精排。计时包含统一的 SQL 调用计数代理，不能直接与上一轮无代理的绝对耗时比较。

首轮与其他验证有并行执行，原始结果单独保留；下表使用验证任务结束后的串行重测。5 次样本只报告中位数，不称为 P95。

| 记录数 | v7 中位耗时 | 旧整窗原文 | 新准入原文 |
|---|---:|---:|---:|
| 1,000 | 10.86 ms | 575.30 ms | **245.96 ms** |
| 10,000 | 126.68 ms | 12,091.25 ms | **4,972.56 ms** |

| 记录数 | v7 每查询数据库读取调用 | 旧整窗原文 | 新准入原文 |
|---|---:|---:|---:|
| 1,000 | 12 | 15,988 | **11,991** |
| 10,000 | 12 | 159,988 | **119,991** |

这些是 `all/get/iterate` 调用次数，不是 SQL 扫描行数。新路线减少了每个锚点重复保护查询，但仍遍历全部准入单元并检查来源，1 万条仍约 5 秒，明显不足以直接接入每轮召回。本轮没有为了跑分增加缓存或新索引。内存是三路线共存进程的合计数，保留原始采样，不归因到某一条路线。
